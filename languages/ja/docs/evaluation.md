# 評価、ベンチマーク、テスト

## 専門家スコアに対する品質

[speechocean762](https://www.openslr.org/101/)（CC BY 4.0、Zhang ら、Interspeech 2021）: 非ネイティブ話者 250 人（中国語が母語、半数は子ども）による 5000 発話を、5 人の専門家が音素（0-2）、単語（0-10）、発話（0-10）のレベルで採点したものです。`data/speechocean762/` に展開してください。ハーネスはパイプラインをプロセス内で実行し（HTTP なし、レート制限なし）、JSONL の出力から再開できます。

```bash
python scripts/speechocean762_eval.py --api v1 --out data/so762-v1-test.jsonl --report data/so762-v1-test-report.json
python scripts/speechocean762_eval.py --api v2 --out data/so762-v2-test.jsonl --report data/so762-v2-test-report.json
python scripts/speechocean762_v2_signal.py data/so762-v2-test.jsonl     # phone correlation, MDD, confusions, latency
```

発話・単語・音素スコアのピアソン相関と、誤発音検出（MDD）の適合率 / 再現率 / F1 を、全話者と成人（18 歳以上）のみについて報告します。「誤発音」とは、専門家の音素スコアが 1.0 未満（音素の約 4%）であることを指します。

| テスト分割 | v1 成人 | v2 成人 | v2 全体 |
| --- | --- | --- | --- |
| 発話の総合 / 正確さ | 0.619 / 0.669 | 0.852 / 0.829 | 0.779 / 0.749 |
| 発話の流暢さ / 韻律 | 0.630 / 0.108 | 0.876 / 0.853 | 0.817 / 0.796 |
| 単語の正確さ | 0.020 | 0.643 | 0.591 |
| 音素の正確さ | 0.033 | 0.630 | 0.590 |
| MDD F1 | 0.269 | 0.537 | 0.480 |

注: v2 の数値は FP32 モデルによるものです。INT8 はすべての指標で 0.004 以内に収まります（完全性は、ラベルにほとんど分散がないルールベースのスコアで、0.010 動きました）。スコア曲線による発話相関の変化は 0.005 以下です。v1 の最大の誤差は、アクセントのある発話に対する ASR の意味不明な出力に由来します。v2 のしくみ: [scoring-v2.md](scoring-v2.md)。

### この結果からわからないこと

- **話者はすべて中国語を母語とする人です。** 他の母語の学習者は、異なる誤りをします（語末子音、th/dh、子音連結、母音の長さ）。他の母語の数値はまだありません。
- スコア曲線の指数の根拠となったサニティクリップは、5 つの合成（gTTS）録音です。
- スコアラーは、20〜30 秒の音声では検証されていません。

### 他の母語向けのデータ計画

ベトナム語を対象にした調査では、**その母語について、発音スコア付きで商用利用できる公開の英語コーパスは見つかりませんでした**。他の母語は調査していません。L2-ARCTIC は 6 つの母語にまたがる 24 人の話者（各 4 人）を収録していますが、音素ラベルは二値のみで、ライセンスも非商用です。speechocean762 は中国語話者のみです。現実的な方法は、speechocean762 のプロトコル（評価者 3 人以上、音素 0-2 / 単語 / 発話）で学習者を録音・アノテーションすることです。母語ごとに、成人話者およそ 50〜100 人・発話 500〜1000 件から始め、その母語についてスコアラーを検証または再キャリブレーションします。

## レイテンシとメモリ

`debugs/benchmark.py` は、実際のパイプラインの所要時間をプロセス内で計測します。`--cpus N` はプロセスを N コアに固定し、N vCPU のホストを模擬します。

```bash
python debugs/benchmark.py --api v1 --cpus 4
python debugs/benchmark.py --api v2 --int8 --cpus 4 --concurrency 2
```

Windows の開発用マシン（論理コア 28）で、gTTS のサニティクリップ（1.2〜4.2 秒）を使って計測した p50（ms）:

| 3.4 秒のクリップ | v1 | v2 FP32 | **v2 INT8** |
| --- | --- | --- | --- |
| 2 vCPU | 610 | 375 | **240** |
| 4 vCPU | 381 | 201 | **125** |

| 並行実行（2 スロット、30 リクエスト） | v1 | v2 FP32 | **v2 INT8** |
| --- | --- | --- | --- |
| 4 vCPU、p50 / p90 ms | 461 / 891 | 155 / 416 | **93 / 271** |
| 4 vCPU、req/s | 3.9 | 8.2 | **13.2** |
| 2 vCPU、req/s | 2.7 | 4.5 | **7.4** |

| メモリ（RSS） | ロード後 | リクエスト処理後 |
| --- | --- | --- |
| v1 | 796 MB | 970〜1090 MB |
| v2 FP32 | 928 MB | 1050〜1170 MB |
| v2 INT8 | **430 MB** | 600〜660 MB |
| v1 + v2 INT8 を 1 プロセスで | 1030 MB | 未測定 |

v2 ではコストのほぼすべてがモデルです（INT8、4 vCPU、3.4 秒のクリップ: ONNX 約 120 ms、アライメント約 3 ms、スコアラー約 1 ms）。INT8 がデフォルトであり、小さなホストでは唯一妥当な選択肢です。FP32 はロード時点で v1 より重くなります。これらは開発用マシンの数値です。INT8 による高速化は CPU の命令セットのサポートに依存するため、クライアントを切り替える前に実際のホストでベンチマークを再実行してください。また、`/evaluate` のたびに、ステージごとのミリ秒を記録した `evaluate_timing` レコードが 1 件ログに出力されます。

## テスト

```bash
pytest tests/ -v
```

約 460 件のテストがあり、API（v1 と v2）、認証とレート制限、音声処理、テキスト/IPA/GOP/韻律のサービス、アライメントと採点ルール、v2 の CTC アライメント（`torchaudio.forced_align` との一致）、特徴量、スコアラー、そして `app/services/v2/` が torch を import しないことを保証するガードを対象としています。実際の v2 モデルファイルが必要なテスト（サニティの帯域、ノイズゲート）は、ファイルがない場合は自動的にスキップされます。`asyncio_mode = "auto"`。

`tests/sanity_dataset/` には、期待スコア帯域付きの合成録音が 5 つ（良好 3、不良 2）あります。再生成するには `scripts/generate_sanity_audio.py` を使います。

**既知の問題:** v1 のサニティケース 2 件（`poor_001`、`poor_002`）は、v1 がそれらのクリップを帯域の上限である 60 をわずかに上回るスコアで採点するため失敗します。v2 は両方に合格します。
